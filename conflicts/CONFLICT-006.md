# 衝突編號：CONFLICT-006

## 狀態：`detected`

## 衝突描述
- **市場開發者（推廣執行者）** 需要：依 US-CC-001,對社群意見領袖發送**個人化**外展訊息,內容需「明確提到該意見領袖的具體作品或觀點」、提供 exclusive 資訊（技術 deep dive、roadmap、訪談機會),目標是讓對方願意產出內容介紹 req
- **社群意見領袖** 需要：依 US-CC-003,**不被要求寫軟文或干涉評論獨立性**;所有外展訊息模板禁止包含「請正面評價」「請幫推」「交換 X 換 Y」等字樣;`content-generator` 的意見領袖外展模板需在 prompt 中明確加入「不要求回報、不干涉評論方向」的約束
- **為什麼衝突**：US-CC-001 的隱含目的(`以便我能快速評估是否值得**產出內容介紹這個工具**`)與 US-CC-003 的禁令(不得要求回報、不得干涉評論方向)在「外展訊息的真實意圖」上產生張力。提供 exclusive 資訊本身就帶有「換取曝光」的隱性對價結構 — 即便文字層面避開所有禁用詞,意見領袖在收到「客製化的、提及我作品的、附帶 exclusive deep dive 與訪談機會」的訊息時,仍會合理推論專案方期待回報。spec 同時要求 (a) 訊息要強到足以促成內容產出,又 (b) 完全不能在語言或結構上暗示期待回報,這兩個目標在真實外展行為中很難同時達成。

## 衝突類型
**功能衝突**(目的明確 vs 手段中立) + **倫理／品牌安全衝突**(轉化目標 vs 評論獨立性保護)

## 相關 User Stories / NFR
- US-CC-001(req-promotion-strategy):個人化外展、提及對方作品、提供 exclusive 資訊
- US-CC-003(req-promotion-strategy):禁止要求回報、禁止干涉評論方向、禁用詞清單
- req-promotion-strategy NFR 安全性「品牌安全」:禁止產出過度行銷、要求回報的內容
- US-MD-011 驗收條件:禁止產出過度行銷或誇大語氣

## AI 分析
這是 spec 自身內部最微妙的張力 — 兩條 US 都是同一位 spec 擁有者寫的,而且都「有道理」,但放在同一個外展模板裡,工程實作會被夾在兩個無法同時最佳化的目標中:

1. **「個人化 + exclusive」本身就是一種隱性對價**:行為經濟學上,提供個人化關注 + 獨家資訊會啟動互惠原則(reciprocity),即使文字層面沒有任何「請幫推」字樣,收件人仍會感受到產出內容的隱性壓力。US-CC-003 的禁令只能管到字面,管不到語用層面。
2. **「exclusive 資訊」與「不期待回報」的邏輯矛盾**:若專案方真的不期待任何回報,為何只給意見領袖 exclusive 而不公開給所有人?exclusive 的存在本身就是篩選機制 — 篩選「值得投資個人化關注的人」,而判斷標準必然與「對方有產出內容的影響力」相關。
3. **驗收條件的可測性落差**:US-CC-003 的驗收條件只能驗證「模板裡沒有禁用詞」,無法驗證「整個外展行為的語用意圖中立」。content-generator 可能完美通過驗收,但實際產出的訊息仍讓意見領袖感到不適。
4. **與 CONFLICT-004 的耦合**:若 content-generator 走雙語(en + zh-TW),禁用詞清單與「中立語氣」的判定在英文與繁中兩種文化語境下標準不一致 — 英文開發者社群對「partnership」「early access」「we'd love to have your perspective」等用語的容忍度,與繁中社群對「合作」「獨家」「期待您的看法」的容忍度不同。雙語雙標準會使「禁用詞」成為持續維護的負擔。
5. **與 US-MD-013 品牌定位文件的耦合**:US-MD-013 要求 spec 擁有者維護一份禁用詞清單作為 prompt context;但禁用詞清單的維護成本與漏網之魚率,直接決定了 US-CC-003 是否真的能落地。
6. **隱含的成功指標衝突**:成功指標 3 要求「至少 5 位社群意見領袖在其內容中主動提及 req 框架」— 若 US-CC-003 被嚴格執行到「外展訊息完全不引導任何方向」,成功指標 3 的達成率會直接下降;反之,若為了達成成功指標 3 而軟化 US-CC-003,則違反品牌安全。

## 解決方案
- [ ] 方案 1:**最大化個人化 — 接受隱性對價的存在並只管字面**(優先滿足 US-CC-001 與成功指標 3)。維持 US-CC-001 的客製化外展與 exclusive 資訊,US-CC-003 的執行範圍縮小到「字面禁用詞 + prompt 注入中立性指令」即可,不嘗試管控語用層面。代價:意見領袖實際感受可能與 US-CC-003 的精神有落差,有損及品牌安全的風險。
- [ ] 方案 2:**最大化中立 — 移除 exclusive 資訊與個人化元素**(優先滿足 US-CC-003 的精神)。改為「公開邀請函」模式:所有 exclusive 資訊(deep dive、roadmap、訪談機會)同步公開於 repo,外展訊息只是「告訴你這些資源存在 + 指向公開頁面」,不提供任何只給特定意見領袖的內容,也不在訊息中提及對方作品。代價:US-CC-001 的「個人化」「exclusive」字面驗收條件完全無法達成;成功指標 3 的轉化率可能大幅下降。
- [ ] 方案 3:**結構化分層外展 — 個人化背景研究 + 中立邀請語**(折衷方案)。content-generator 將外展訊息拆成兩段:第一段是「為什麼是你」(引用對方作品 + 解釋為何 req 與其關注的領域相關,純粹是脈絡說明),第二段是「我們提供什麼」(統一的 exclusive 資源清單,所有意見領袖都拿到相同的內容,沒有依個人客製化的差別待遇)。第二段語氣固定為「here's what's available if you're curious — no expectations, no need to reply」。Prompt 層強制這兩段分離,並由 spec 擁有者人工審核每一封首次接觸訊息(不只審模板,審實際內容)。同時補一條驗收條件:「每封外展訊息發送前必須通過 spec 擁有者人工 review,且 review 紀錄保留 12 個月」。代價:人工 review 會成為市場開發者時間瓶頸(見 CONFLICT-007),且無法透過全自動 pipeline 規模化。
