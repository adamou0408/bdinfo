# 衝突編號：CONFLICT-002

## 狀態：`detected`

## 衝突描述
- **市場開發者** 需要：蒐集潛在客戶的詳細資料（企業名稱、規模、聯絡方式、產業、需求特徵）以進行精準行銷（US-MD-001）
- **潛在客戶** 需要：個人隱私與企業資料受到保護，不希望資料被未經授權地蒐集與使用（隱含於 US-PC-001 的退訂機制需求）
- **為什麼衝突**：市場開發者需要越多資料才能越精準地接觸客戶，但從公開資料源大規模蒐集企業資訊可能涉及個資法規疑慮，且潛在客戶可能對「被陌生人掌握自己的資訊」感到不安。

## 衝突類型
**權限衝突**（資料蒐集 vs. 隱私保護）

## 相關 User Stories
- US-MD-001：自動從公開資料源識別企業
- US-PC-001：尊重客戶意願，提供退訂機制

## AI 分析
此衝突涉及法律合規（台灣個人資料保護法）和商業倫理的雙重考量。

關鍵觀察：
1. 台灣個資法規定，即使是公開資料，蒐集與利用仍需有特定目的且符合比例原則
2. 傳統產業企業的公開資訊（如：公司登記、招標紀錄）通常屬於企業資訊而非個人資料，法律風險較低
3. 但若涉及企業負責人或聯絡人的個人聯絡方式，則進入個資保護範圍
4. Spec 中已包含安全性需求（資料分類、加密、審計日誌、資料刪除機制），顯示已有初步意識

## 解決方案
- [ ] 方案 1：**僅蒐集企業公開資訊**（優先滿足潛在客戶）— 限制資料源為政府公開資料（如：商工登記、招標公告），不蒐集個人聯絡方式。透過社群媒體的公開互動來建立聯繫，而非主動取得私人聯絡資訊。
- [ ] 方案 2：**分級資料策略**（折衷方案）— 第一階段僅蒐集企業級公開資訊（公司名、產業、規模）；第二階段當客戶透過社群互動表達興趣後，才請求個人聯絡資訊並取得明確同意。所有資料附帶來源標記和蒐集日期。
- [ ] 方案 3：**完整資料蒐集 + 嚴格合規框架**（優先滿足市場開發者）— 從多種公開資料源蒐集完整資訊，但建立嚴格的合規機制：明確告知資料用途、提供查詢/刪除管道、定期清理過期資料、完整審計日誌。
