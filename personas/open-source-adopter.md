# 開源框架採用者（Open-Source Framework Adopter）

## 基本描述
- **誰是這個角色**：在個人專案、新創或企業內部評估與採用新型開發工具／框架的開發者、技術主管或獨立接案者;會在 GitHub、Dev.to、HackerNews、Reddit、Twitter/X 等開發者社群尋找能提升生產力的工具
- **主要職責**：評估新框架是否值得納入工作流、試用後決定是否長期採用、在團隊或社群中推薦、遇到問題時回報 issue 或自行 fork
- **技術熟悉度**：熟練（熟悉 Git、CLI、至少一個主流語言生態、能閱讀 README 並執行 quickstart）
- **使用頻率**：每天（評估階段密集試用,採用後融入日常工作流）

## 核心需求
- 最在乎:**第一眼能否理解「這工具解決我什麼問題」**、上手成本是否低、文件是否完整(特別是英文文件)、是否有 demo 或 case study 可參考、授權條款是否清晰(能否商用)、專案是否活躍(最近 commit / release / issue 回應速度)
- 最怕:文件只有一種語言(尤其非英文)、沒有 demo 只有抽象描述、看不到 star/貢獻者等社會證明、專案半死不活、授權條款不明導致商用風險、被迫學習新的抽象概念卻看不到實際好處
- 典型工作場景:瀏覽 HackerNews Show HN / Reddit r/programming / Dev.to 首頁發現新工具 → 點進 GitHub README → 掃讀 30 秒決定是否深入 → 跑 quickstart → 試用 15 分鐘 → 決定 star / fork / 拋棄

## 與其他角色的關係
- 會和哪些角色互動:市場開發者/專案維護者(尋求支援)、社群意見領袖(閱讀其推薦的工具)、團隊同事(分享採用決策)、其他採用者(在 issue/discussion 交流經驗)
- 常見的利益衝突點:想要最新功能 vs 需要穩定可靠;想要完整客製化 vs 希望 out-of-the-box 就能用;想免費使用 vs 需要企業級支援
