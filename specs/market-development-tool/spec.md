## 需求摘要
市場開發者擁有 AI 全端開發、企業系統升級、一條龍開發維護與顧問服務的技術能力，但無法有效接觸到有真實需求且願意付費的客戶。需要建構一個持續性的市場開拓工具，自動化潛在客戶發掘、外展接觸、關係管理與銷售管道追蹤的流程，讓技術服務提供者能夠專注於交付價值，而非耗費大量時間在手動尋找客戶上。

## 使用者故事

### 市場開發者（Market Developer）

**US-MD-001**
- **作為**市場開發者，**我想要**系統能自動從公開資料源（如企業官網、社群平台、招標公告、新聞報導）識別有 AI 開發或系統升級需求的企業，**以便**我不用手動搜尋就能獲得精準的潛在客戶名單。
- **驗收條件**：
  - [ ] 系統能從至少 3 種公開資料源抓取**傳統產業**企業資訊（如：製造業、農業、營建、物流等）
  - [ ] 系統能根據預設關鍵字與條件篩選出資訊化程度較低、有系統升級潛在需求的企業
  - [ ] 每日自動更新潛在客戶名單
  - [ ] 名單包含企業名稱、產業、規模、聯絡方式等基本資訊
  - [ ] 介面語言為繁體中文

**US-MD-002**（依 CONFLICT-001 決議調整：社群互動優先）
- **作為**市場開發者，**我想要**系統能根據市場洞察與潛在客戶特徵，自動產生有價值的社群內容（案例分享、產業洞察、技術趨勢），**以便**我能在社群媒體上持續經營專業形象，吸引潛在客戶主動來詢問。
- **驗收條件**：
  - [ ] 系統能根據目標產業（傳統產業）的痛點與趨勢，自動草擬社群貼文內容
  - [ ] 支援多種內容類型：案例分享、產業洞察、技術科普、成功故事
  - [ ] 內容模板可自訂與調整
  - [ ] 以**社群媒體**為主要發布管道（如：Facebook、Instagram、LINE）
  - [ ] 發布前需要人工確認與微調
  - [ ] 提供內容排程功能（定期定時發布）
  - [ ] 追蹤內容互動數據（觸及率、按讚、留言、分享、私訊詢問）

**US-MD-003**
- **作為**市場開發者，**我想要**一個銷售管道追蹤儀表板，能清楚看到每個潛在客戶從發現到成交的完整狀態，**以便**我能有效管理銷售流程、不遺漏任何商機。
- **驗收條件**：
  - [ ] 儀表板顯示各階段（發現→接觸→溝通→提案→成交）的客戶數量
  - [ ] 可以記錄每次互動的時間、方式、結果（完整追蹤，依 CONFLICT-003 決議）
  - [ ] 首次接觸時透明告知資料使用方式
  - [ ] 提供客戶隨時查看和刪除自己資料的權利
  - [ ] 系統自動提醒需要跟進的客戶（超過 N 天未互動）
  - [ ] 支援匯出報表

**US-MD-004**
- **作為**市場開發者，**我想要**系統提供市場洞察分析（如需求趨勢、競爭動態、熱門產業），**以便**我能制定更精準的市場策略。
- **驗收條件**：
  - [ ] 展示當前市場中 AI/系統開發需求的趨勢變化
  - [ ] 識別需求成長最快的產業或領域
  - [ ] 每週自動產生市場洞察摘要

### 潛在客戶（Prospective Client）

**US-PC-001**
- **作為**潛在客戶，**我想要**收到的接洽內容是針對我的實際需求量身打造的，**以便**我能快速判斷這個服務是否值得進一步了解。
- **驗收條件**：
  - [ ] 接洽內容明確提到客戶的產業與可能痛點
  - [ ] 包含具體的解決方案方向（而非泛泛的推銷）
  - [ ] 提供簡單的回覆或預約管道
  - [ ] 尊重客戶意願，提供退訂機制

**US-PC-002**
- **作為**潛在客戶，**我想要**能方便地查看服務提供者的過往案例與能力證明，**以便**我能在決策前建立信任感。
- **驗收條件**：
  - [ ] 提供線上作品集或案例展示頁面
  - [ ] 案例包含問題描述、解決方案、成果數據
  - [ ] 支援客戶證言或推薦信

## 非功能需求
- 效能：潛在客戶名單更新延遲不超過 24 小時；儀表板載入時間 < 3 秒
- 相容性：支援主流瀏覽器（Chrome、Firefox、Safari、Edge）；行動裝置響應式設計
- 語言：繁體中文（zh-TW）
- CRM：需從零建構內建 CRM 功能（無既有系統整合需求）

## 安全性需求
- 資料分類：內部（潛在客戶基本資訊）/ 機密（聯絡方式、互動紀錄）
- 認證需求：需要登入，僅市場開發者角色可存取
- 授權需求：角色型存取控制（RBAC），不同層級看到不同資訊
- 加密需求：傳輸中加密（TLS）；靜態加密（客戶聯絡資訊）
- 審計日誌：記錄所有外展活動、資料存取、名單匯出操作
- 個資處理：涉及企業聯絡人 PII，需符合個資法規；提供資料刪除機制
- 合規框架（依 CONFLICT-002 決議）：明確告知資料用途、提供查詢/刪除管道、定期清理過期資料（超過 12 個月未互動）、完整審計日誌、資料來源標記
